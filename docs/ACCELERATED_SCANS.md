# Paged CPU and CUDA scans

`kryptos.accelerated.scan_batch(request, backend="cpu", offset=0, batch_size=1024, top=10)` scans a bounded page of the exact general or scheduled affine plaintext family. The request has the same cipher/model inputs as `optimize-plus`, including an explicit frozen `model_path`. Optimizer frontier options are reported as ignored because this API enumerates pages. No training corpus is downloaded or inferred.

The affine family has independent coordinates over F2 followed by F13. The rightmost coordinate changes fastest, and every distinct plaintext occurs once; redundant key assignments were already projected out by the existing algebra solver. Pass the returned `next_offset` to continue. `complete` means this page reaches the end, **not** that earlier pages were scanned. Total, offsets, and candidate assignment indices also have decimal-string fields for lossless browser handling beyond 2^53. An algebra resource cutoff returns `feasible: null`; an exact contradiction returns false and a zero family size.

CPU ranking compares the exact integer objective `product(count*q+p)`, where `p/q` is the exact stored binary floating smoothing parameter. Windows touching any supplied crib are omitted completely, preserving gaps. Ties sort by plaintext and then assignment index. `score_exact` and `exact_objective_hex` are hexadecimal integer strings, so Python consumers use `int(value, 16)`. `score` is the model's mean log probability, or null if no unmasked windows exist. Compare objective integers only for the same frozen model and window/mask layout. When merging pages, preserve the same request/model/source hashes.

CUDA uses actual compiled kernels for mixed-radix coordinates, integer affine letter generation, and float64 sparse ngram lookup/summation. It keeps at least 64 or four times `top` candidates for exact CPU rescoring, then applies the same final tie order. If the shortlist covers the whole page, page ranking is exact; otherwise `ranking_exact_within_page` is false. CPU rescoring cannot prove that a floating shortlist omitted no better candidate. Every retained candidate has CPU-verified letters, a complete encryption recipe, intermediate stage outputs, and literal CPU re-encryption and crib checks. A high rank, fit, or round trip never authenticates a Kryptos solution.

Explicit `backend="cuda"` reports failure instead of silently falling back. `backend="auto"` alone allows CPU fallback and records why. `probe_backend()` verifies a compiled one-thread kernel, plus driver/runtime/device information. The server may cache this hardware probe; readiness should be refreshed after environment changes.

The CPU path is dependency-free and updates sparse nonzero affine entries with an odometer, avoiding a dense coordinate product for each new candidate. Two prepared families are cached by normalized request, model-file hash, and source hashes. CUDA modules are cached by device. The scanner never writes checkpoints itself; offset paging and app job storage remain separate.

Limits are 65,536 candidates per page, 100 retained candidates, 50 million conservative affine letter operations, 5 million ngram window evaluations, and 4 million bits per exact objective. Reduce `batch_size` if the work cap is exceeded. Existing algebra caps remain enforced. These are finite operation caps, not hard real-time deadlines. Source/model preparation, initial CUDA compilation, and CPU replay add overhead.

## Optional CUDA environment

Use a project-owned Python environment and a compatible NVIDIA driver. The versions tested here are Python3.12.2, `cupy-cuda12x==14.2.0`, `nvidia-cuda-runtime-cu12==12.9.79`, and `nvidia-cuda-nvrtc-cu12==12.9.86`. NumPy and cuda-pathfinder are transitive dependencies. Do not install more than one CuPy distribution in an environment. CuPy documents [installation](https://docs.cupy.dev/en/stable/install.html) and [RawKernel compilation](https://docs.cupy.dev/en/stable/reference/generated/cupy.RawKernel.html).

For sandboxed Windows workers, point `TEMP`, `TMP`, and `CUPY_CACHE_DIR` at a writable project cache directory before starting Python. The CUDA wheels must be installed in the actual executing environment; putting another environment's packages on `PYTHONPATH` can prevent CUDA header/NVRTC discovery. No other project's environment needs modification.

Run CPU controls with `.venv/Scripts/python.exe -m unittest discover -s tests -p test_accelerated.py -v`. Set `KRYPTOS_TEST_CUDA=1` for the explicit real-GPU controls. They compare exact CPU rankings against CUDA pages small enough for full CPU rescoring, check non-involutive gathers, all three equations, a nonstandard alphabet, scheduled recipes, zero dimensions, and offsets greater than 2^53. A larger CUDA page separately checks its approximate-ranking label and retained candidate verification.

The canonical release run `research/runs/release-L-002/accelerated/` records three synthetic pages (6,201 candidates per backend),60 independent retained score/recipe checks and unchanged source/input hashes. On the RTX2060, the4,096-candidate general page took about0.889s CPU and0.202s CUDA; the2,048-candidate scheduled page took0.475s and0.089s. These observed timings include per-page rescoring, replay and sensitivity reporting, exclude the earlier readiness compilation, and do not predict every workload. All ten retained texts agreed in these examples; the larger CUDA pages still carry approximate-ranking flags. Earlier development timings describe earlier code and remain historical.

Reproduce in a fresh output path with `.venv/Scripts/python.exe research/accelerated_benchmarks.py --cuda --output NEW_RESULT.json`. The script requires actual CUDA when `--cuda` is present, verifies scores independently from plaintext strings, and performs no K4 or K5 search. Development evidence remains separate from the project's canonical manifests.
