# Paged CPU and CUDA scans

`kryptos.accelerated.scan_batch(request, backend="cpu", offset=0, batch_size=1024, top=10, ranking_mode="certified")` scans a bounded page of the exact general or scheduled affine plaintext family. The request has the same cipher/model inputs as `optimize-plus`, including an explicit frozen `model_path`. Optimizer frontier options are reported as ignored because this API enumerates pages. No training corpus is downloaded or inferred.

The affine family has independent coordinates over F2 followed by F13. The rightmost coordinate changes fastest, and every distinct plaintext occurs once; redundant key assignments were already projected out by the existing algebra solver. Pass the returned `next_offset` to continue. `complete` means this page reaches the end, **not** that earlier pages were scanned. Total, offsets, and candidate assignment indices also have decimal-string fields for lossless browser handling beyond 2^53. An algebra resource cutoff returns `feasible: null`; an exact contradiction returns false and a zero family size.

CPU ranking compares the exact integer objective `product(count*q+p)`, where `p/q` is the exact stored binary floating smoothing parameter. Windows touching any supplied crib are omitted completely, preserving gaps. Ties sort by plaintext and then assignment index. `score_exact` and `exact_objective_hex` are hexadecimal integer strings, so Python consumers use `int(value, 16)`. `score` is the model's mean log probability, or null if no unmasked windows exist. Compare objective integers only for the same frozen model and window/mask layout. When merging pages, preserve the same request/model/source hashes.

CUDA uses compiled kernels for mixed-radix coordinates, integer affine letter generation, and sparse ngram lookup. The default `certified` mode encloses each positive integer factor's scaled log2 with integer-only outward rounding, sums those intervals on the GPU, and retains every interval whose upper endpoint reaches the kth greatest lower endpoint. Exact CPU arithmetic compares all retained overlaps, including ties, using the same plaintext/index ordering. This proves exact ranking **within the evaluated page**. Tied or poorly separated scores can require rescoring the entire page; a speedup is not promised. Before upload, a conservative check prevents uint64 interval-sum overflow.

The opt-in `ranking_mode="approximate"` uses float64 summation and keeps at least64 or four times `top` candidates for exact CPU rescoring. If that shortlist does not cover the whole page, `ranking_exact_within_page` is false. Every retained candidate in either mode has CPU-verified letters, a complete encryption recipe, intermediate stage outputs, and literal CPU re-encryption and crib checks. A high rank, fit, or round trip never authenticates a Kryptos solution.

Explicit `backend="cuda"` reports failure instead of silently falling back. `backend="auto"` alone allows CPU fallback and records why. `probe_backend()` verifies a compiled one-thread kernel, plus driver/runtime/device information. The server may cache this hardware probe; readiness should be refreshed after environment changes.

The CPU path is dependency-free and updates sparse nonzero affine entries with an odometer, avoiding a dense coordinate product for each new candidate. Two prepared families are cached by normalized request, model-file hash, and source hashes. Immutable CUDA model/affine buffers are cached by prepared family, device and ranking mode; modules are cached by device. `certification.immutable_device_cache_hit` exposes buffer reuse. The scanner never writes checkpoints itself; offset paging and app job storage remain separate. An explicit `score_mask` can omit additional zero-based positions but must include all supplied crib positions; every window crossing the mask is removed, preserving gaps.

`PersistentWorkerPool(size, python=None, env=None, cwd=None, folder=...)` keeps1..4 hidden processes. `execute(job, cancel=None, timeout=60)` is thread-safe; the timeout includes queue wait and startup. Slots start lazily and use unique file inboxes, atomic response publication and request identifiers. `close()` releases processes, including their CUDA contexts. Cancellation raises `WorkerCancelled` (an `InterruptedError`); timeout raises `TimeoutError`; failure or changed package sources raises `WorkerFailure`. An affected worker is discarded and the next call starts a fresh process. Source hashes are checked before and after execution. The caller advances durable offsets only after accepting a complete response; the pool does not claim an interrupted page was evaluated. An abandoned idle worker exits after five minutes. One-shot workers remain supported.

Windows virtualenv executables can redirect to another interpreter process. Worker ownership therefore covers the whole descendant job, using atomic [process creation with a Job List](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-updateprocthreadattribute) and a non-inherited [kill-on-close Job Object](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects). Closing the owner or killing a worker also terminates its redirected interpreter. The implementation requires Windows10 or later; POSIX uses a private process group. Private file operations retry sharing/access failures for at most two seconds; they never retry a completed computation or advance a page themselves.

The integer interval certificate uses96 fractional bits internally to enclose normalized factors in[1,2), then repeated squaring extracts up to32 binary log digits. Every multiplication/division rounds outward. When the next digit cannot be decided, the remaining suffix is enclosed without guessing. Thus each summed lower bound is at most the true scaled log-product and each upper bound at least it. A discarded upper bound is strictly below at least `top` lower bounds; equal endpoints remain eligible. This bound does not depend on a floating-point error estimate. The certificate reports interval candidates, eliminated candidates, maximum interval width and exact CPU comparisons.

Limits are 65,536 candidates per page, 100 retained candidates, 50 million conservative affine letter operations, 5 million ngram window evaluations, and 4 million bits per exact objective. Reduce `batch_size` if the work cap is exceeded. Existing algebra caps remain enforced. These are finite operation caps, not hard real-time deadlines. Source/model preparation, initial CUDA compilation, and CPU replay add overhead.

## Optional CUDA environment

Use a project-owned Python environment and a compatible NVIDIA driver. The versions tested here are Python3.12.2, `cupy-cuda12x==14.2.0`, `nvidia-cuda-runtime-cu12==12.9.79`, and `nvidia-cuda-nvrtc-cu12==12.9.86`. NumPy and cuda-pathfinder are transitive dependencies. Do not install more than one CuPy distribution in an environment. CuPy documents [installation](https://docs.cupy.dev/en/stable/install.html) and [RawKernel compilation](https://docs.cupy.dev/en/stable/reference/generated/cupy.RawKernel.html).

For sandboxed Windows workers, point `TEMP`, `TMP`, and `CUPY_CACHE_DIR` at a writable project cache directory before starting Python. The CUDA wheels must be installed in the actual executing environment; putting another environment's packages on `PYTHONPATH` can prevent CUDA header/NVRTC discovery. No other project's environment needs modification.

Run CPU controls with `.venv/Scripts/python.exe -m unittest discover -s tests -p test_accelerated.py -v`. Set `KRYPTOS_TEST_CUDA=1` for the explicit real-GPU controls. They compare exact CPU rankings against certified CUDA pages, check non-involutive gathers, all three equations, a nonstandard alphabet, scheduled recipes, zero dimensions, offsets greater than2^53, deliberately tied scores requiring full-page comparison, and device-buffer reuse. A larger opt-in approximate page separately checks its label. Integer-power oracles validate interval endpoints, including deliberately coarse internal precision that forces wider enclosures. Pool controls are in `tests/test_worker_pool.py`.

The historical release run `research/runs/release-L-002/accelerated/` predates certified ranking and persistent workers. It records three synthetic pages (6,201 candidates per backend),60 independent retained score/recipe checks and unchanged source/input hashes. Its approximate GPU timings and labels apply to that saved source revision. They do not measure the current certified implementation.

Reproduce in a fresh output path with `.venv/Scripts/python.exe research/accelerated_benchmarks.py --cuda --output NEW_RESULT.json`. The script requires actual CUDA when `--cuda` is present, verifies scores independently from plaintext strings, and performs no K4 or K5 search. Development evidence remains separate from the project's canonical manifests.

Compare20 pages using `.venv/Scripts/python.exe research/persistent_benchmarks.py --cuda --output NEW_RESULT.json`. It measures one-shot and persistent workers end-to-end, compares exact CPU/certified-GPU rankings, independently verifies each retained objective and recipe, and checks active cancellation, crash recovery and timeout recovery. Run against stable package sources; concurrent source edits deliberately invalidate the run. A fresh companion artifact directory preserves one-shot inputs/results. OS and filesystem caches are not flushed, and measured speedups apply only to these declared synthetic pages.

For a bounded provenance record, run `.venv/Scripts/python.exe research/run_persistent_audit.py --audit-skill PATH_TO_COMPUTATION_AUDIT_SKILL --label FRESH_LABEL`. It snapshots package/benchmark/test/model inputs, declares the finite experiment, imposes a180-second experiment limit, and validates the resulting manifest against source/input/output hashes. A195-second ownership watchdog encloses the external audit runner and terminates all owned descendants during cleanup. The numerical thread cap is cooperative; the GPU kernels still execute normally.

The current canonical result is `research/runs/release-M-002/persistent/result.json`, with a validated adjacent manifest and portable source/input snapshot at `research/source_snapshots/release-M-002-persistent/`. All20 page rankings agreed across all four combinations, and240 retained scores/recipes were independently checked. Each mode/backend evaluated5,120 candidates. CPU one-shot versus persistent wall time was18.539s versus5.414s (3.42×); CUDA was75.974s versus5.285s (14.38×). Certified CUDA compared61 exact overlapping candidates per5,120-candidate run;19 of20 persistent pages reused device buffers. Active cancellation, forced worker crash and timeout all restarted successfully. The complete audit took109.438s under its180-second bound. These are sequential synthetic-workload observations with unflushed caches, not a general speed guarantee. The preserved `release-M-001` result applies to its earlier source snapshot, before the repeated-close guard and elapsed-time fix.
