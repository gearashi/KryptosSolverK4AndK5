# Unknown column-order recovery

This module infers the order in which whole occupied columns were read. The earlier 59-route family supplied every gather permutation in advance; this family supplies a geometry and vertical reading direction, then solves for the column order. It does not infer an unknown surrounding substitution. A separately established transformation can be undone before calling the module, with that assumption recorded by the caller.

## Contract and API

`kryptos.columnar.recover_column_order(ciphertext, cribs, *, width=None, cells=None, column_direction="top_to_bottom", max_segmentations=2048, max_states=200000, max_candidates=20, time_limit_seconds=5)` is dependency-free. Crib starts are one-based original plaintext positions. Supply exactly one geometry: a row-filled width, or an explicit cell list in source-stream order. The latter supports the K4 occupied-cell surrogate: four cells at columns28–31 followed by three full31-letter rows. No padding, missing sculpture letters, or null cells are invented. Absolute sculpture origins are not inferred. Column labels are retained even if negative or nonconsecutive.

For any proposed order, encryption concatenates the columns sorted by row, ascending for `top_to_bottom` and descending for `bottom_to_top`. Its gather convention is `C[j] = P[permutation[j]]`. Column direction is supplied for the entire model; per-column reversals are not included. Inputs contain 1–4096 ASCII letters and at most64 occupied columns. Upper resource bounds are1,000,000 segmentations,5,000,000 charged states,1,000 stored candidates, and600 seconds. Defaults are much smaller. The monotonic deadline is checked between bounded operations; it is not an operating-system process kill.

The finite assertion is existence/counting of a pure whole-column transposition fitting the supplied cribs. A fit is a consistency witness, never authentication. A complete zero result excludes only that supplied family. A cutoff is inconclusive beyond its rigorous lower bound. Every saved full candidate contains the inferred possible order, exact gather recipe, literal reencrypted ciphertext, a human-readable technique description, supplied assumptions, and hashes of the normalized request and implementation source.

## Exact reductions and optimization

First, each supplied plaintext letter must occur at least as often in the ciphertext. This is a necessary condition for every pure transposition, independent of geometry. Failure gives an immediate exact rejection.

Equal-length columns split ciphertext unambiguously into chunks. For ragged occupancy, enumerate distinct orders of the multiset of column lengths. The count is `w! / product(multiplicity!)`; for the K4 surrogate it is `31 choose4 =31,465`. These length segmentations partition all labelled column orders without duplicates.

Within one segmentation, connect a chunk slot to each equal-length source column whose known letters agree at their vertical offsets. A valid column order is exactly a perfect matching of this bipartite graph. An augmenting-path matching rejects Hall obstructions. Relative to one perfect matching, any other usable edge lies on an alternating cycle. Strongly connected components of the directed alternating graph therefore remove precisely the edges that occur in no perfect matching. This both propagates forced assignments and gives exact edge support.

Connected components of the supported graph factor the number of matchings. A memoized subset recurrence counts each component exactly, using a fixed slot order. Complete bipartite components instead contribute their factorial immediately. This tangible symmetry optimization can count20! ambiguous orders without enumerating them. Candidate enumeration follows only positive-count prefixes and stores at most the requested number. A storage limit does not itself stop counting.

For every supported chunk–column edge, transporting its chunk letters to source positions gives exact marginal plaintext domains. Union these domains over every feasible segmentation. A singleton is forced within the declared family. Column domains are likewise unions of supported labels for each output slot. Domains are globally valid only after complete search; all such fields are withheld after truncation, rather than converting unexplored ambiguity into apparent recovery.

The reported `total_column_orders` distinguishes column orders, even if identical column contents produce the same plaintext. The exact distinct-plaintext count is returned only when every order was stored or when every plaintext position is forced (then it is1). Otherwise it remains unknown. A unique plaintext does not imply a unique order.

## Budgets, failure, and evidence

`work.states` charges segmentation-prefix visits, chunk–column comparisons, augmenting-edge visits, support-graph edges, newly memoized counting states, and representative-enumeration nodes. All have bounded local work under the input limits. Work counters also report tested/feasible/rejected segmentations, removed edges, memo hits and factorial shortcuts. The segmentation limit counts fully proposed length patterns, whether feasible or not. On a state/time cutoff after a matching was found but before counting finished, that single witness contributes1 to the rigorous lower bound; already completed segmentation counts remain included. No unsupported upper or exact count is emitted.

The narrow unit command is `python -m unittest discover -s tests -p test_columnar.py -v`. Its independent oracle enumerates all labelled permutations for geometries with3–6 columns, then compares solution sets, counts, column domains and plaintext domains. Controls include a non-involutive10-letter ragged gather, explicit sparse coordinates, reversed columns, a Hall-forced edge,20! symmetry, duplicate plaintexts, count-only operation, invalid input, state/segmentation/time cutoffs, and inventory rejection.

The reusable benchmark command is `python research/columnar_benchmarks.py --output NEW_RESULTS_PATH.json`. It creates its output exclusively and hashes all direct scientific inputs before and after. Parent orchestration records a bounded canonical run and manifest separately. Its seven predeclared cases are PK2 hidden order, a ragged hand vector, a six-column hidden order, insufficient cribs, supported-edge propagation,20! ambiguity, and canonical K4 inventory rejection. Default per-case limits are fixed before execution.

PK2 uses `research/source_snapshots/sculpture-J/pk2_fixture.json` (SHA256 `ee1dfbf1a56cd7a7825f382c1081b58bd64717c9933d2897b2d2ce37c13b6ddb`). Its350-letter ciphertext is from the cached official challenge. The first-person published result supplies width7 and reading order `[1,3,4,0,5,2,6]` (MARGINS), but abbreviates an interior plaintext passage. The source agent reconstructed the full text and independently matched the published SHA256 prefix `4288fc09c000c915`, both unabbreviated prose portions, and the literal roundtrip. Recovery receives width7 and only21 plaintext crib letters (first14 and last7), never the answer order or keyword. The fixture answer is consulted afterward to validate recovery. This is a known-answer control with withheld order, not independent evidence about K4.
