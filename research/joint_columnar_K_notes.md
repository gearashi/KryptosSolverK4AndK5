# Joint column order and repeating key

This adds an inference problem that neither earlier solver covered: the column order and the substitution key are both unknown. `columnar.py` assumes pure transposition; the general layer solver requires the complete gather permutation. The new module couples these uncertainties through their common crib equations. No plaintext language score removes an assignment.

## Predeclared contract

`recover_joint_columnar(ciphertext, cribs, *, period, order="ST", cipher="vigenere", alphabet="kryptos", width=None, cells=None, column_direction="top_to_bottom", max_segmentations=2048, max_states=200000, max_candidates=20, time_limit_seconds=5)` lives in `kryptos/joint_columnar.py`. It uses the pinned `columnar.py` input, matching, supported-edge, and component-counting helpers; no existing source file is modified.

Supply one declared period, one known shared alphabet, and either a row-filled width or an explicit list of occupied cells in plaintext-stream order. No holes are filled. ST substitutes before gathering; TS substitutes afterward. Gather means `C[j]` takes the intermediate letter at `permutation[j]`. Crib starts are one-based original plaintext positions. Vigenere uses `C=P+K`, Beaufort `C=K-P`, and variant Beaufort `C=P-K`, with indices modulo 26.

For a ciphertext chunk assigned to a source column, each crib gives a numeric key requirement. Its phase is source position modulo period for ST, output position modulo period for TS. An edge with contradictory requirements for one phase is impossible. Different edges must also agree on shared phases: existence of a perfect column matching alone is insufficient. For example, plaintext AA, ciphertext AB, width 2 and period 1 admits a perfect unconstrained column matching but requires two different values of the single additive key.

The finite assertion is feasibility and counting for this declared geometry/rule/alphabet/period model. Exact totals are labelled column orders and assignments to key phases actually used by the finite message. Unvisited key slots are explicitly `?` and excluded from assignment counts. Counts never silently quotient repeated keys, equal plaintexts, or equivalent models at other periods. A complete zero excludes only this supplied model. A cutoff exposes lower bounds and witnesses, with exact counts and global forced values withheld.

## Safe pruning and factorization

For each distinct ordering of the multiset of column lengths, form a chunk-to-column bipartite graph carrying key requirements. Propagation removes edges incompatible with key domains; perfect matching rejects all-different obstructions; alternating-cycle support removes edges belonging to no perfect matching. For each key phase, every output slot and every source column must select an incident edge. Intersecting the unions of the incident edge requirements therefore safely narrows that phase's domain. These operations repeat to a fixed point.

If a remaining edge still requires an unresolved key phase, branch on a coupled column slot, preferring small domains. Assigning an edge can constrain several shared phases and prune the other slots. Branches partition labelled column orders; distinct length segmentations also partition them. There is no score-based rejection.

A further exact shortcut applies once every surviving edge equation is implied by singleton key domains. Then every supported perfect matching and every completion of the remaining independent key domains is valid. Component matching counts multiply the key-domain cardinalities. Complete bipartite components contribute their factorial immediately. This avoids enumerating both free permutations and free keys: a no-crib, 20-column, period-3 example counts `20! × 26^3` without a branch. The shortcut is not applied while an edge can still conflict with an unresolved shared key.

Within each factored block, transporting every supported edge and every allowed key value yields exact marginal plaintext domains. Union these over all completed blocks. Column and numeric key marginals are accumulated similarly. These are exact global domains only after exhaustive completion. The distinct-plaintext count is generally unknown, because different orders can collide. It is exact when all positions are forced, when there is only one feasible column order (key-to-plaintext is injective on used phases), or when all order families were stored and every used key is resolved.

## Evidence, canonical keys, and limits

Saved candidates describe an order's entire key family. Unknown key letters and plaintext positions remain `?`; partial families have no fabricated full plaintext or replay assertion. A complete finite plaintext gets a standard encryption recipe, both literal intermediate strings, ciphertext equality, and input/source hashes. A key may still contain `?` in unvisited slots; those recipes remain replayable because the message never accesses the slots. No candidate is authenticated automatically.

A fully known declared key is reduced to its shortest repeating period for metadata. Partial keys are never arbitrarily completed to obtain a shorter key. Complete finite operators additionally get a signature over the gather map, shared alphabet, plaintext sign, and output-position numeric shifts. This recognizes equivalent complete encryptions across declared periods and ST/TS descriptions when they induce the same finite map. It is intentionally conservative across different alphabets. Raw model counts remain unchanged; totals across periods must not be summed as disjoint solutions.

Input limits are 4096 letters, 64 occupied columns, and period 1–256. Upper user-settable caps are 1,000,000 length segmentations, 5,000,000 charged states, 1000 saved order families, and 600 seconds. Matching visits, support edges, key checks, phase support scans, propagation/search nodes, counting states and candidate enumeration are charged. The time limit is cooperative, checked between bounded operations. A storage cap does not stop exact counting. Parent bounded execution provides an outer wall-clock cap.

## Validation and planned K4 scope

The focused command is `python -m unittest discover -s tests -p test_joint_columnar.py -v`. Tests use independent exhaustive enumeration of all labelled orders and numeric keys on small rectangular/ragged cases, covering all three rules and both stage orders. Other controls cover a non-involutive hand gather, sparse negative coordinates, reversed columns, a different known alphabet, partial and unvisited key phases, matching-only false positives, canonical signatures, factorization, and cutoff semantics.

The development benchmark is `python research/joint_columnar_K.py --output NEW_PATH.json`. Its ten predeclared controls include six synthetic substitutions wrapped before/after source-verified PK2, one ragged hand fixture, an unresolved-key case, the factorial/free-key shortcut, and a matching-only false positive. PK2 recovery receives width 7, period 3, the cipher rule and stage order, and its first 14 and last 7 plaintext letters. The published column order and synthetic DOG key are withheld; their values are consulted only after recovery. This is a synthetic layered use of a verified fixture, not a revised claim about PK2's published method. Control caps are 200,000 states, 2048 segmentations, 20 stored order families and 5 seconds per case.

Only the parent's canonical run should enable `--include-k4`. Its family is fixed in advance: row-filled widths 7, 8 and 10; periods 2, 3 and 4; ST and TS; Vigenere; the known KRYPTOS alphabet; canonical 97-letter ciphertext and 24 crib positions. These are 18 declared models, each capped at 20,000 states, 128 segmentations, 3 stored order families and 1 second, in one process. Widths are supplied mathematical layouts, not claimed sculpture geometry. The script records every exact rejection, witness and truncation separately, hashes all scientific inputs before/after, and writes only a fresh output path. No broader K4 scan, GPU job, K5 ciphertext assumption, or authentication claim is part of this work.

## Development observations

The ten development controls at `research/manual-checks/joint-columnar-K/controls.json` passed in 0.133 seconds, charging 4999 states. Five of the six substitution-wrapped PK2 cases recovered one order/key/plaintext. ST Vigenere retained two complete texts with the same recovered DOG key: the 21 supplied crib letters do not distinguish exchanging columns 0 and 5. The planted order and text are among them. This ambiguity was preserved rather than resolved using the benchmark answer or language scoring.

The ragged TS hand fixture had one joint solution. The partial-key fixture had two orders and 1352 assignments to used key phases, with no fabricated complete plaintext. The symmetry shortcut counted `20! × 26^3 = 42,760,685,695,712,624,640,000` joint assignments with zero branches. The matching-only counterexample was rejected by shared-phase support. The development run did not include K4; the parent's bounded canonical record is authoritative for the 18-model probe once run.
